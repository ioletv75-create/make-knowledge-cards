# make-knowledge-cards

一个把文章变成知识卡片的 Agent Skill。给它一段文章或一个本地 `.md` / `.txt` 文件，
它输出 **5～8 张知识卡片**，每张包含四段结构：**标题 / 核心知识 / 简明解释 / 例子或自测问题**。

---

## 1. 解决什么问题

读完一篇好文章，过几天能回忆起来的往往只剩下一个模糊印象。想复习，又不想重读全文；
想记笔记，手动提炼既慢又容易漏掉重点。

这个 Skill 解决的就是**从文章到可复习卡片**的这一步。它做三件具体的事：

- **筛选** —— 从全文里挑出真正重要的知识点，丢掉背景铺垫、作者介绍、营销话术和修辞性重复。
- **结构化** —— 把每个知识点压成固定四段式，让卡片能被快速扫读、自测。
- **守住诚实** —— 只使用原文已有的信息。原文只够讲 3 个知识点，就交付 3 张卡片，
  而不是硬凑到 8 张。**原文没有的信息，一律不补。**

它不解决什么：不做网页抓取、不解析 PDF、不导出 Anki、不提供图形界面。这些边界在
下文「明确不做的事」中列出，Skill 遇到这类请求时会直接说明不支持并给出替代方式。

---

## 2. 主要功能

| 功能 | 说明 |
| --- | --- |
| 文章 → 卡片 | 支持**直接粘贴正文**，或指定本地 **`.md` / `.txt`** 文件路径 |
| 固定四段结构 | 每张卡片：标题、核心知识、简明解释、例子或自测问题 |
| 重要度筛选 | 按「忘掉它是否会真的损失理解」筛掉次要内容 |
| 一卡一知识点 | 一张卡片只讲一件事，避免卡片内部堆砌 |
| 自动去重 | 合并导语、正文、结语中重复出现的同一主张，包括只差笼统程度的近似重复 |
| 不编造 | 卡片内容必须能在原文中找到出处，不引入外部事实、数字或人名 |
| 数量诚实 | 只在 5～8 张区间内输出；原文不足 5 个知识点时如实输出更少并说明原因 |
| 落点字段二选一 | 每张卡片只带**一个**落点：有具体案例就用例子，内容抽象就用自测问题 |
| 语言跟随原文 | 中文原文输出中文字段（核心知识 / 简明解释 / 例子 / 自测），英文原文输出英文字段 |
| 输出前自检 | 输出前逐张过 8 项质量门禁，不通过的卡片直接删除而非含糊改写 |

实现上**没有任何脚本、依赖或构建步骤**——规则本身就是实现。

## 3. 安装方法

Skill 是一份纯文本目录，不需要编译或安装依赖。你只需要把它放到宿主程序能发现的位置。

### 目录内容

```
make-knowledge-cards/
├── SKILL.md          # 规则、字段约定、质量门禁（Skill 的本体）
└── agents/
    └── openai.yaml   # 界面展示配置（显示名、简介、默认提示词）
```

`agents/openai.yaml` 仅供宿主程序读取界面信息，不参与卡片生成。

### 方式一：放到用户级 Skill 目录（推荐）

自本仓库取得 `make-knowledge-cards` 整个目录，放进宿主的用户级 Skill 目录：

```bash
# DSH（用户级目录为 ~/.dsh/skills/）
cp -r skills/make-knowledge-cards ~/.dsh/skills/
```

Windows PowerShell：

```powershell
Copy-Item -Recurse skills\make-knowledge-cards "$env:USERPROFILE\.dsh\skills\"
```

放到用户级目录后，在**任何**项目里都能使用这个 Skill。

> 其他宿主（如 Claude Code、Codex）的 Skill 目录约定请以其官方文档为准。DSH 同时还会
> 读取 `$DSH_AGENTS_HOME/skills/`，未设置该变量时默认为 `~/.agents/skills/`。

### 方式二：放到项目级 Skill 目录

只希望某个项目能用时，把目录放进该项目的 Skill 目录：

```
<项目根目录>/.dsh/skills/make-knowledge-cards/
<项目根目录>/.agents/skills/make-knowledge-cards/
```

DSH 的项目根目录判定方式是从当前目录向上查找 `.git`；找不到时就把当前工作目录当作
项目根目录。

### 方式三：目录不在默认位置

本仓库把 Skill 放在 `skills/` 下（便于一个仓库收纳多个 Skill）。如果你的宿主支持配置
自定义 Skill 目录，把本仓库的 `skills` 目录加进去即可，无需复制。

### 校验（可选）

`SKILL.md` 的 YAML frontmatter 已通过官方 `quick_validate.py` 校验通过：

```
$ python quick_validate.py skills/make-knowledge-cards
Skill is valid!
```

该校验脚本来自官方 skill-creator 工具集（`init_skill.py` / `quick_validate.py`）——
本 Skill 就是用这套官方工具初始化的。脚本只依赖 `pyyaml`，未随本仓库分发，
需要时从上游获取后对 Skill 目录运行即可。

## 4. 使用方法

### 直接粘贴文章

```
用 make-knowledge-cards 把下面这篇文章做成知识卡片：

<粘贴文章正文>
```

### 指定本地文件

```
用 make-knowledge-cards 处理 docs/xxx.md
```

支持 `.md` 和 `.txt`。

### 斜杠调用

若宿主支持直接调用 Skill（DSH 使用 `/名称` 形式），也可以写成：

```
/make-knowledge-cards 把这篇文章做成卡片
```

### 语言

不指定时跟随原文语言。也可以明确要求：中文原文输出中文字段，英文原文输出英文字段
（**Core** / **Explanation** / **Example** / **Self-test**）。

## 5. 输入输出示例

### 输入

原文（节选，`HTTP 缓存机制入门`）：

> 浏览器每次请求资源都要经过网络，网络往返（RTT）是主要的延迟来源。缓存的核心价值不是"让数据变快"，而是"让这次请求不必发生"。
>
> `Cache-Control` 是响应头里控制强缓存的字段。最常用的是 `max-age`，单位是秒。这表示 3600 秒内浏览器可以直接使用本地副本，不会向服务器发出任何请求。注意这是"不发请求"，连 304 都不会有，所以它是延迟最低的方案，但代价是这段时间内服务器完全失去了对内容的控制权。
>
> `no-cache` 这个名字容易误解。它不是"不缓存"，而是"缓存但每次都必须向服务器确认"。真正不缓存的是 `no-store`。
>
> 对于 `app.a1b2c3.js` 这类带内容哈希的文件名，构建工具通常会配置为一年过期（`max-age=31536000, immutable`）。因为内容一旦变化，文件名就会变化，变成一个全新的 URL，也就不存在"旧缓存读到新内容"的问题。反过来，`index.html` 绝对不能这样配，因为它的 URL 永远不变。

### 输出

```markdown
## 1. 缓存收益的来源：消除网络往返

- **核心知识**：缓存的价值不是"让数据变快"，而是"让这次请求不必发生"。
- **简明解释**：延迟主要来自网络的往返时间（RTT）；把结果存在本地后，重复访问直接省掉整次往返。
- **例子**：同一份资源被重复使用时，第一次从服务器取回并存在本地，第二次访问直接使用本地副本。

## 2. 强缓存 `max-age`：零请求与失控期的取舍

- **核心知识**：`max-age` 指定的时间内浏览器直接使用本地副本，不发出任何请求，连 304 都没有。
- **简明解释**：这是延迟最低的方案，但代价是这段时间内服务器完全失去对内容的控制权。
- **例子**：`Cache-Control: max-age=3600` 表示 3600 秒内浏览器不会向服务器发出任何请求。

## 3. `no-cache` 与 `no-store` 的区别

- **核心知识**：`no-cache` 不是"不缓存"，而是"缓存但每次都必须向服务器确认"；真正不缓存的是 `no-store`。
- **简明解释**：两个指令名字相近，但一个保留本地副本只强制校验，另一个完全不写入缓存。
- **自测**：要把内容配置成"完全不缓存"，应该用哪个指令？`no-cache` 的实际行为又是什么？

## 4. 内容哈希文件名与"强缓存拉满"

- **核心知识**：URL 会随内容变化的资源可以配一年强缓存；URL 永远不变的 `index.html` 绝不能这样配。
- **简明解释**：更新能力由文件名变化承担，而不是由缓存过期承担，所以"强缓存拉满"与"能更新"可以同时成立；反之 URL 不变的文件一旦被强缓存一年，用户就永远拿不到新的资源引用。
- **例子**：`app.a1b2c3.js` 配 `Cache-Control: max-age=31536000, immutable` 是安全的；`index.html` 这样配则会锁死更新。
```

每张卡片只带**一个**落点字段（例子或自测）。第 4 张把原文中"哈希文件名可以长期强缓存"
和"`index.html` 不能这样配"合并为一张卡片——它们是一体两面，不是两个独立知识点。

### 原文不足时

若原文只有一两段、只够支撑 3 个知识点，输出就是 3 张卡片，并附一句说明：

```markdown
## 1. …

## 2. …

## 3. …

源文本较短（两个段落），仅支持生成 3 张卡片；要继续增加卡片，就只能复述同一观点或引入源文本之外的内容。
```

这是**预期行为**，不是失败。要求凑满 8 张，等于要求编造。

---

## 明确不做的事

- 不抓取网页，不做爬虫。
- 不支持 PDF、DOCX、图片、音频。
- 不导出 Anki（`.apkg`）或任何记忆软件格式。
- 不提供图形界面。

遇到这些请求时，Skill 会直接说明不支持，并给出替代方式（粘贴正文，或改用本地 `.md` / `.txt`）。

---

## 质量门禁

每张卡片在输出前都要通过 8 项检查：

1. **可溯源** —— 每句话都出自原文，没有外部事实、数字或人名。
2. **单一知识点** —— 一张卡片只讲一件事。
3. **不重复** —— 没有第二张卡片重复同样的主张，包括它的更笼统或更具体的版本。
4. **够重要** —— 去掉它，读者会真的损失理解。
5. **可独立阅读** —— 不依赖其他卡片，例子本身也是自足的。
6. **只用一个落点字段** —— 例子或自测二选一，不能同时出现。
7. **具体** —— 例子来自原文，或问题仅凭原文即可回答。
8. **数量诚实** —— 卡片数量由原文决定，而不是由目标数量决定。

第 1 项不通过的卡片直接删除，而不是改写得更含糊。
